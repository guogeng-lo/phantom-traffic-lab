## 設計想法

讀者自己點開、自己操作，沒有人講解。所以每一頁都要讓讀者**先做一件事，再看到解釋**，不是先讀一段字。

整份的節奏：

1. **先看到怪事**：沒有車禍，車流自己卡住。
2. **自己動手**：點一台車煞一下，看事情怎麼擴大。
3. **看懂方向**：用時空圖看出車往前、塞車往後。
4. **猜，再驗證**：什麼條件下會放大。兩題都是一般人直覺容易猜錯的。
5. **回到真實世界**：真的實驗、能不能解決、模型的限制。

整份簡報都會清楚標出內容屬於哪一種：

| 標示 | 意思 |
|---|---|
| 【實驗】 | 論文裡真的車、真的路 |
| 【模型】 | 論文裡的方程式或電腦模擬 |
| 【我們的模擬】 | 我們自己寫的程式，在瀏覽器裡即時算的 |

標示的樣子只是暫定，視覺風格等大綱確認後再提案。

## 逐頁

### 第1頁｜沒有車禍，車流也會自己卡住

- **讀者看完能說出**：沒有紅綠燈、沒有障礙物，車流也可能從一個很小的偏差，變成走走停停。
- **畫面**：
  - 【我們的模擬】一個環狀道路，22台車等距、等速地繞，**只有一台車一開始往前偏了一點點**。
  - 這台車在畫面上標出來，寫明「這是我們故意放的很小的偏移」。
  - 不用操作，十幾秒後這個小偏移長成一團塞車。
  - 偏移多大、多久會長成塞車，要在`model/`先測。
- **文字**（主線）：
  - 「完全均勻、完全沒有偏差的模型不會自己改變，所以我們放了一個很小的偏移。」
  - 2008年日本做過真的實驗：230公尺的環道、22台車，先以約30 km/h均勻地繞。開始後，車距的小波動自然出現並逐漸變大，3分鐘時已經有一團5台車的塞車。
  - 真實實驗裡的小波動從哪裡來，論文沒有細分；這裡不替它下結論。
  - 【實驗】附出處和論文連結，不搬用沒有確認授權的照片或影片。
- **證據卡**：
  - 【實驗】`sugiyama2008-setup`、`sugiyama2008-jam-emerges`
  - 【模型】`bando1995-spontaneous-jam`：Bando的模擬也是讓第1台車往前偏0.1。
- **要小心**：
  - 畫面是我們的模擬，文字講的是真的實驗，兩者要分開標。
  - 不能寫「實驗證明了這個模型」。
  - 不能把模擬描述成「無緣無故自己出現擾動」。偏移是我們設定的。

### 第2頁｜只要有人輕踩一下煞車

- **讀者看完能說出**：一點點的減速，會在後面的車越變越大，最後變成一團停住的車。
- **互動**（必要功能）：
  1. 一開始車流是均勻的。
  2. 讀者**點任何一台車**，它就短暫減速一下。
  3. 接著看後面的車一台接一台慢下來，最後擠成一團。
  4. 「重來」可以回到均勻車流再試一次。
  - 真的在瀏覽器裡跑模型，不是預錄動畫。
- **三層**：
  - **主線**：「你只是讓一台車慢了一下，後面的車卻越擠越多。」
  - **知識**：最佳速度模型（Optimal Velocity Model, OVM）：每個駕駛只看跟前車的距離，決定自己想開多快，再慢慢把車速調過去。
  - **進階**：模型方程式`dv/dt = a[V(h) − v]`、速度函數`V(h) = tanh(h − 2) + tanh2`，以及參數。
- **證據卡**：`bando1995-ovm-equation`、`bando1995-velocity-function`、`bando1995-spontaneous-jam`（模型）。另外要新增一張【我們的模擬】卡，記錄我們的模擬用的參數和`model/`的對答案測試。
- **要小心**：
  - 「踩一下煞車就塞」是**模型裡**的事。
  - 真實實驗沒有說是誰踩了煞車。Sugiyama看到的是車距的小波動自然出現、慢慢變大。`disputes.md`的「火種」那條也說了，要分開「擾動從哪來」和「擾動怎麼長大」。
  - 這一頁只講「怎麼長大」。

### 第3頁｜車往前開，塞車卻往後跑

- **讀者看完能說出**：每台車都是往前開，但「塞住的那一段」一直往後移；塞車團一直在，裡面的車一直在換。
- **互動**（必要功能：時空圖先追一台車，再疊上其他車）：
  1. 沿用第2頁剛剛那次的模擬，在旁邊畫時空圖。
     - **橫軸是位置，縱軸是時間，時間往下增加**（使用者決定）。
     - 圖上標兩個箭頭：車子前進的方向、塞車波傳播的方向。
     - 環道沒有起點和終點：車子繞過圖的右邊界時，軌跡要從左邊界接下去，不能畫一條橫跨整張圖的線。
     - 取樣要夠密，避免畫出假的方向（選題階段出過這個錯）。
  2. 第一步只畫**一台車**的軌跡：線往右下斜；開進塞車時幾乎停住，線變成接近垂直往下；出來後又斜回去。
  3. 讀者按「疊上其他車」，22台車的軌跡一次出現，塞車的地方連成一條**往左下斜的帶子**，跟車子前進的方向相反。
  4. 預測小問題：「這條帶子往哪邊移？」先選，再揭曉。
- **三層**：
  - **主線**：「車是往前開的，但塞車這件事一直往後傳。」
  - **知識**：時空圖（time-space diagram）、走走停停波（stop-and-go wave）、塞車團（jam cluster）。
  - **進階**：模擬裡的波速（無因次）怎麼從圖上的斜率讀出來。
- **證據卡**：
  - 【實驗】`sugiyama2008-backward-wave`：真實環道約20 km/h往後。
  - 【實驗】`tadaki2013-density-dependence`：30台時約20 km/h往後。
  - 【模型】`bando1995-spontaneous-jam`：模型裡的塞車團也往後移。
- **要小心**：
  - 模擬是無因次的，不能說模擬的波速是20 km/h。
  - 20 km/h只能跟真實實驗放在一起講。

### 第4頁｜擾動往後傳，在這組條件下越傳越大

- **讀者看完能說出**：前車慢下來，後面的車要一段時間才能把車速調好，這段時間裡車距被吃掉，只好煞得更多；在第2頁那組條件下，擾動就這樣往後傳、越傳越大。
- **互動**：
  - 用第2頁那次的模擬，畫出被點的那台車後面幾台車的**車速隨時間的變化**（例如後面第1、5、10、15台）。
  - 讀者會看到減速的低谷一台接一台往後傳，在這組條件下整體越來越深。
  - 畫面上寫出這組條件：a、車距、22台。
  - 旁邊放一個對照：同樣點一下，但換成第5頁「調整夠快」的條件，低谷會越傳越淺。
- **三層**：
  - **主線**：「不是誰故意亂開。每個人都要一點時間才把車速調好，在這組條件下，擾動就一台傳一台地放大。」
  - **知識**：敏感度（sensitivity）a：駕駛把車速調向想開的速度有多快。
  - **進階**：這個模型刻意不加反應延遲，「要一點時間才調好」來自加速度方程式本身，跟「反應延遲」是兩回事。
- **證據卡**：
  - 【模型】`bando1995-linear-stability`、`bando1995-no-delay`
  - 【我們的模擬】車速變化的圖，需要新卡。
- **要小心**：
  - **不保證每一台車的最低速度都比前一台低。**擾動在傳的過程中不一定每一台都單調變深，畫面和文字只講「指定條件下整體怎麼傳、怎麼放大」。
  - 實際的圖要等`model/`跑出來再決定挑哪幾台車、怎麼描述。
  - 「要一點時間才調好」是我們的教學說法，不是論文原話，要在逐頁稿審查確認沒有扭曲原意。
  - 不能說成「反應延遲」，Bando的模型沒有延遲。

### 第5頁｜猜猜看①：每台車更快調整速度，還會塞嗎？

- **讀者看完能說出**：調整得夠快（敏感度夠大）時，小擾動會自己消失；不夠快時會放大。中間有一條清楚的分界。
- **互動**（必要功能：先猜再跑）：
  1. 問題：「如果每台車都更快把車速調到想開的速度，剛剛那團塞車還會出現嗎？」
  2. 讀者先選：會／不會／看調多快。
  3. 選完才能拉滑桿調a，再點車煞一下，看結果。
  4. 揭曉：22台車、車距2時，分界在a約1.96。比它小就放大，比它大就消失。
- **三層**：
  - **主線**：「有一條分界線：調整得夠快，波會自己平掉；不夠快，就越滾越大。」
  - **知識**：線性穩定性分析（linear stability analysis）：看很小的擾動會變大還是變小。
  - **進階**：
    - 論文的條件`V'(b) < a/2`，是車數很多（長波）時的極限。
    - 22台車要用有限車數的修正`a = V'(b)(1 + cos(2π/N))`，算出1.9595。
    - 我們的模擬量到1.95966。
    - a = 1.98時，照a/2條件應該不穩定，模擬裡卻是衰減的，這正是有限車數的差別。
- **證據卡**：`bando1995-linear-stability`（模型）、`ours-finite-n-threshold`（推導）、`ours-finite-n-simulation`（模擬）、`orosz2010-ring-stability`（綜述的推導，用來交叉核對）。
- **要小心**：
  - 「分界1.96」是這組參數（式(24)、車距2、22台、沒有延遲）的結果，不是真實駕駛的數字。
  - a是「調整速度有多快」，**不是駕駛的反應時間**。模型裡沒有反應延遲，a也是無因次的，不能翻成「反應時間幾秒」。
  - 整頁的用詞都用「調整」，不用「反應」。

### 第6頁｜猜猜看②：車越多，越容易塞嗎？

- **讀者看完能說出**：環的長度固定時，車太少不會放大，車太多也不會放大，**中間那段最容易**；但「不會放大」不等於「開得快」，車太多時是大家一起慢慢走。
- **互動**（必要功能：調車數，先猜再跑；正確處理環長、平均車距和有限車數）：
  1. 環長固定（跟第2頁一樣），問題：「車越多越容易塞？」
  2. 讀者先選：越多越容易／越少越容易／中間最容易。
  3. 選完可以用滑桿選車數再跑，也可以按「一次全部跑」，看一張「哪些車數會放大」的結果條。
  4. 揭曉：放大只發生在中間一段。
     - 依推導公式（a = 1、環長44），理論預測的不穩定車數是16到39台。使用者也獨立用公式核對過，但這是理論預測，**正式模型仍要對照測試**。
     - 44台時均勻車流的速度約0.2024（無因次），大家一起慢慢地走。
- **三層**：
  - **主線**：「車太多也不一定會出現走走停停，可能是大家一起慢慢擠著走。最容易出問題的，是看起來還能開、其實已經太擠的時候。」
  - **知識**：臨界密度（critical density）；介穩態（metastable state）：同一個密度有時順、有時塞。
  - **進階**：
    - 速度函數的斜率`V'(b)`在車距2時最大，兩邊都變小，所以兩端穩定。
    - Bando圖10的穩定區和不穩定區（示意圖）。
- **證據卡**：
  - 【模型】`bando1995-stable-regions`、`ours-finite-n-threshold`；
  - 【實驗】`tadaki2013-density-dependence`：25台順、30台塞、34台塞車團時有時無。
  - 【實驗】`tadaki2013-critical-density`：作者估每公尺0.08～0.09台。
  - 【實驗】`tadaki2013-metastable`、`tadaki2013-high-density`：40台那一場是均勻的，但只有一場，作者也說還不確定。
  - 車數掃描的結果是【我們的模擬】，需要新卡。
- **要小心**：
  - 「太擠也穩定」一定要講清楚是「小擾動不會放大」，不是「不塞」。
  - Tadaki的40台只有一場，而且作者自己說不確定，只能放在知識或進階層，不能當成主線的實驗證據。
  - 模擬的「車數」和實驗的「密度」不能直接對數字。模擬是無因次的，Tadaki的環長是314公尺。

### 第7頁｜真的路上也是這樣

- **讀者看完能說出**：這不只是電腦裡的事，真的車、真的人開，也看得到同樣的現象。
- **畫面**：
  - 把三個實驗的關鍵數字畫成一張我們自己做的比較圖或表：
    - Sugiyama：230公尺、22台、塞車團約20 km/h往後。
    - Tadaki：314公尺、車數不同、密度的分界。
    - Stern：260公尺、21～22台，三場都出現波。
  - 加上高速公路的比較：Sugiyama說實驗的波速跟高速公路上量到的差不多。
- **三層**：
  - **主線**：「真的實驗看得到同樣的事：沒有障礙物也會出現走走停停，塞車往後跑。」
  - **知識**：基本圖（fundamental diagram）：流量和密度的關係。
  - **進階**：
    - 三個實驗的條件差異：環長、車數、量測方式。
    - 實驗的重複次數和限制。
- **證據卡**：`sugiyama2008-backward-wave`、`sugiyama2008-highway-comparison`、`tadaki2013-setup`、`tadaki2013-density-dependence`、`stern2018-setup`、`stern2018-waves-emerge`（全部是實驗）。
- **要小心**：
  - 高速公路的比較是作者引用別人的資料，不是他們自己量的。
  - 三個實驗的條件不一樣，不能合成一個數字。

### 第8頁｜一台車能把波撫平嗎？

- **讀者看完能說出**：在Stern那個特定的環道實驗裡（260公尺、21～22台、只有一台車可以控制），讓那一台車照大家的平均速度開、不跟著前車忽快忽慢，波就明顯變弱；但做不好也會把波帶回來。這是那個實驗的結果，不是保證任何道路都會這樣。
- **畫面**：
  - 【實驗】Stern 2018的結果，用我們自己畫的長條圖。
    - 打開控制後，車速的標準差下降：A約81%、B約50%、C約55%。
    - 油耗也下降。
    - 通過量A、B增加，C反而小降2.5%。
  - 【實驗】「做不好會怎樣」：實驗A把目標速度調得比車流快，波又回來了。
- **互動（探索中，使用者已批准探索）**：【我們的模擬】平滑車模擬。
  - 先在`model/`測幾種**我們自己設計的簡化規則**，確認真的有效、而且有教學價值，才放進HTML。例如：
    - 照最近一段時間的平均速度開
    - 速度變化設上限
    - 目標車距拉大
  - 測之前先寫好比較項目和「有效」的標準，再跑，不看結果才改標準。
  - 如果有效，讀者可以把其中一台車換成平滑車，再點別的車煞車，比較有沒有平滑車時的差別。
  - **第三題先猜再跑（探索目標）**：「平滑車開得比大家快，會更好嗎？」
    - 只有模型實測支持時才製作，不預設結果。
    - 結果可能跟Stern實驗A一樣（調太快波會回來），也可能不一樣；不一樣就照實寫，或者不做這題。
  - 畫面上要分清楚：這是我們設計的規則，Stern實驗用的是另外三種控制器。
- **三層**：
  - **主線**：「在這個環道實驗裡，不用每台車都變聰明，一台車開得穩，整條車流就好很多。至於真實道路上能不能做到，這個實驗沒有回答。」
  - **知識**：自動駕駛車（autonomous vehicle, AV）、平滑車。
  - **進階**：三種控制方式（A：FollowerStopper；B：受訓駕駛照同類策略開；C：PI控制器），以及各自的條件。
- **證據卡**：`stern2018-setup`、`stern2018-controllers`、`stern2018-results`、`stern2018-wave-returns`（實驗）。平滑車模擬是【我們的模擬】，需要新卡。
- **要小心**：
  - 我們的平滑車規則是自己設計的，**不是**Stern的控制器，畫面上要明寫。
  - 「一台車就能改善」只能限定在Stern這個特定的環道實驗，不能寫成普遍的保證。
  - 表3比的是「表現最好的控制時段」，不是整段平均。
  - 「調太快會把波帶回來」只有實驗A支持。

### 第9頁｜模型沒有告訴你的事

- **讀者看完能說出**：剛剛的模擬是一種簡化的解釋，不是唯一的答案；它有它的假設。
- **畫面**：幾張可以展開的卡片：
  - **所有駕駛都一樣**：真的人每個都不一樣。
  - **沒有隨機性**：另一個常用的模型（NaSch）用隨機減速當火種，也做得出塞車，兩種模型的假設不同，不判誰對。
  - **沒有反應延遲**：延遲夠大時，最先失穩的可能變成短的波。
  - **單車道、不能超車**。
  - **無因次**：我們沒有把模擬換成公尺和秒。
  - **實驗場次少**：每種條件只有一兩場。
- **證據卡**：`nagel1992-randomization`、`nagel1992-circle-jams`、`orosz2010-delays`、`orosz2010-ovm-family`，以及`disputes.md`的相關幾條。
- **要小心**：Kerner的立場我們沒讀過，不能寫。

### 第10頁｜用你自己的話說說看

- **互動**：三題輕量測驗，對應三個學習目標。
  - 每題先選答案，選了才揭曉對錯和解釋，並寫答案在第幾頁。
  - 不計分、不儲存任何資料。
  - 題目大致是：

    2. 車往前開，為什麼塞車波往後跑？
    3. 在模型裡，什麼條件下小擾動會放大？
- **最後**：
  - Wiki和全部文獻的連結。
  - 「這份簡報怎麼做出來的」的連結，連到repo和檢查紀錄。
