# 節點6 逐頁稿審查的判定標準

送審之前寫好、commit（AGENTS第8節、production-plan的E）。審查包由`scripts/make_page_review_package.py`產生，會把這份標準原文放在最前面。這份標準要改，要先問使用者，並在`runs/`記錄是不是看過審查結果才改的。

## 審查什麼

只看逐頁稿（`pipeline/pages/`）跟它連到的證據卡之間的關係。證據卡本身已經通過節點3的忠實度審查（論文卡）或`model/`的測試（我們的卡），這一關**不重審卡片有沒有讀對論文**。

三件事：

1. **有沒有超出證據**：頁面上的說法、數字、條件，證據卡支不支持。特別看：
   - 把模型或模擬講成真實道路的結果。
   - 把只在特定條件下成立的結果（例如22台、車距2、a=1、某一個實驗）講成普遍的事。
   - 把只有一場、只有一個地點、作者自己說不確定的結果講成確定。
   - 【實驗】【模型】【我們的推導】【我們的模擬】的標示放錯。
2. **生活化的說法有沒有扭曲原意**：主線用一般人的話講，可以省略細節，但不能讓意思變了。例如「要一點時間才調好」不能讓讀者以為模型有反應延遲。
3. **會不會誤導**：沒有交通流背景的讀者，照頁面讀下來，會不會得到錯的結論；先猜再揭曉的題目，正確答案和解釋是不是跟證據一致。

不審：中文文筆、視覺設計、程式能不能做到（那是節點7）、卡片本身有沒有讀對論文。

## 嚴重程度

| 程度 | 意思 |
|---|---|
| 會誤導讀者 | 讀者照頁面讀，會得到跟證據不符的結論。例如把模型講成實驗、數字或條件錯、把特定條件的結果講成普遍、標示錯成另一種證據 |
| 不精確 | 方向對，但用詞或條件不夠精確；讀者不會因此得到錯的結論 |
| 小問題 | 用詞、重複、順序之類，不影響意思 |

## 判定

- **通過**：審查回覆裡沒有任何一條「會誤導讀者」。
- **不通過**：有任何一條「會誤導讀者」。
- 審查者的意見不直接照改。每一條都回到證據卡（必要時回到論文或`model/`的log）核對：
  - 核對後同意的，照Loop規則只改那一頁、那一處。
  - 核對後不同意的，在紀錄裡寫理由和根據；如果是「會誤導讀者」而我們不同意，交給使用者決定，不自己判通過。
- 「不精確」「小問題」核對後同意的也要改。通過的那一輪如果還有這兩種問題，改完跑`scripts/check_pages.py`，不另外送審；紀錄裡逐條寫改了什麼。
- 不通過時，改完先跑`scripts/check_pages.py`（錯誤要是0），再產生下一輪的審查包，附上這一輪的審查原文，請審查者確認有沒有改好、有沒有引入新的問題。
- 同一關最多3輪。核心主張沒有證據或有重大科學錯誤，立刻暫停那個主張，交給使用者。
- 改了證據卡或slide-map，節點5（`scripts/check_slide_map.py`）也要重跑。
