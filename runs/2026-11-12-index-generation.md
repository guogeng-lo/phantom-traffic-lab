# 索引結構改善：index.md的文獻表和證據卡清單改成自動產生

- **類別**：索引結構改善（不是Graph的節點）
- **日期**：2026-11-12
- **依據**：使用者第3輪後的決定第2點
- **改的檔案**：
  - `scripts/check_wiki.py`：產生規則`render_index`和同步檢查
  - `scripts/build_index.py`（新）：重建或比對索引
  - `wiki/index.md`
  - `tests/test_check_wiki.py`
  - `AGENTS.md`第2、5、9節

## 為什麼要改

同一個研究主張存了兩份：證據卡的「主張」一份，`wiki/index.md`的手寫摘要一份。卡片一改，摘要就過期。

- 第2輪審查：11條新問題裡有5條是索引摘要沒跟著卡片改。
- 第2輪我把39列摘要全部對照過一次，同一輪還是又漏改一列（`orosz2010-ring-stability`沒加N≥3）。
- 第3輪逐列核對，索引不一致18條，其中16條是摘要太短、漏掉條件。

原本的`check_wiki.py`只檢查索引有沒有列出每張卡、連結存不存在，不比對內容。改之前，用舊版檢查現在的repo（`runs/logs/2026-11-12-index-before.log`）：

```
文獻 6 篇（算進5篇的獨立論文 6 篇），證據卡 39 張（pending 0 張）。
錯誤 0 個，警告 0 個。
exit=0
```

這時索引裡`orosz2010-ring-stability`那列還是「環上N台車，沒有延遲時最先不穩定的是最長的波」，卡片已經有N≥3，舊版檢查照樣通過。

## 怎麼改

**單一事實來源**：文獻檔和證據卡。索引裡重複的資訊都從它們產生。

- `index.md`用兩行HTML註解標出自動產生的區塊。標記外面的介紹和導覽，人工寫，程式不動。
- 文獻表：id、種類（`kind`）、閱讀狀態（`read_status`）、連結。
  - 原本手寫的「全文已讀（arXiv預印本）」變成欄位原文「全文已讀」。版本資訊本來就在文獻檔的`read_scope`裡。
- 證據卡依文獻分組，每張列出：
  - id和連結
  - 類型（`type`）、狀態（`status`）
  - 條件（`conditions`欄位原文）
  - 主張（卡片「## 主張」全文，不縮寫）
  - 我們自己的推導和模擬放在最後一組。
- 「條件」是我加的，使用者的清單裡沒有明寫。理由：使用者要求不能為了縮短而刪掉研究條件；有些卡的主張寫「在這組條件下」，條件寫在`conditions`欄位，只放主張會看不出是哪組條件。這是用卡片既有的欄位，39張卡都沒有改。
- 主張裡的相對連結是從`cards/`出發寫的，放進索引時改成從`wiki/`出發。例如`bando1995-linear-stability`連到`ours-finite-n-threshold.md`，在索引裡變成`cards/ours-finite-n-threshold.md`。
- `python3 scripts/build_index.py`：重寫標記之間的內容。
- `python3 scripts/build_index.py --check`：只比對，不同步就結束代碼1。
- `check_wiki.py`：每次都重新產生一次，跟檔案比對，不同就報錯。
  - 卡片改了沒重建、或有人手改了產生的區塊，都擋得下。
  - 產生規則只有`check_wiki.py`裡的一份，`build_index.py`直接用它，兩邊不會不一樣。

## 測試

`tests/test_check_wiki.py`：

- 測試用的假Wiki改成用`build_index.py`產生索引。
- 原本有3個情境會改到卡片主張、狀態，或新增文獻。照新規定，這種改動之後要重建索引，所以在這3個情境裡加上重建這一步：
  - 主張裡只有年份，units寫無數值（改主張）
  - 科普當成實驗證據（新增文獻）
  - 沒有confirmed卡的論文不算（改狀態）
- 原本有兩個情境直接改索引的寫法，配合新格式改了：
  - 「索引沒列卡片」：拿掉卡片連結。
  - 「索引列了不存在的卡」：在人工導覽裡加一個壞連結。
  - 要擋的東西不變。

新加10個情境：

| 情境 | 預期 |
|---|---|
| 改了卡片的主張沒重建索引 | 擋（不同步） |
| 改了卡片的狀態沒重建索引 | 擋 |
| 改了卡片的條件沒重建索引 | 擋 |
| 改了文獻的閱讀狀態沒重建索引 | 擋 |
| 新增卡片沒重建索引 | 擋 |
| 手改自動產生的摘要 | 擋 |
| 自動產生的標記被刪掉 | 擋（找不到標記） |
| 改了卡片也重建索引 | 通過 |
| 改人工寫的導覽 | 通過，不用重建 |
| 主張裡的相對連結 | 在索引裡改成從wiki出發，連結檢查通過 |

結果：`共69個情境，失敗0個。`（`runs/logs/2026-11-12-index-generation-tests.log`）

這10個新情境沒有拿去舊版跑。舊版沒有產生索引的程式，假Wiki建不起來，比較沒有意義。舊版擋不下過期摘要的證據，是上面那份實際repo的log。

## 跟第3輪那18條的關係

- 1條（`orosz2010-ring-stability`沒有N≥3）：索引現在放的是卡片主張全文，已經包含N≥3。
- 1條（`stern2018`閱讀狀態文字）：現在直接用`read_status`欄位。
- 16條（摘要漏條件）：索引不再有另外寫的摘要，改放主張全文和`conditions`。

主張全文本身條件夠不夠，是卡片的問題，不是索引的問題。這要第4輪審查才能確認，這裡不先宣稱已經解決。

## 這個改變的代價

- 索引變長，從一頁表格變成39段。
- 導覽要靠分組和人工寫的介紹。
- 之後如果想要短摘要，要在證據卡加一個欄位，同樣由程式產生，不能再回到手寫。
