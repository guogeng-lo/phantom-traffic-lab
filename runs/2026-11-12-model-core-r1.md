### M2沒通過的原因

**理論預測的16～39台其實都對上了。**這一項沒通過，是我設計的量法有三個漏洞：

1. **衰減太快的車數，掉到浮點誤差的底**（N = 10～14）：
   - k=1的波從10^−6衰減，在t = 1000～1500左右掉到約10^−12，之後就不再變小，這是浮點誤差的底。
   - 回歸把這段平的也算進去，量出來的衰減率偏小。
   - 標準裡沒有寫「掉到太小就停止」。
2. **其他的波長得比k=1快**（N = 28～32）：
   - a = 1時，k=3、k=4的波成長率比k=1大好幾倍。它們從浮點誤差長大，量到最後時已經是k=1的20～40倍。
   - 量出來的成長率因此比理論高3～5%，超過容許誤差。
   - 標準只在k=1超過10^−3時停止，沒有考慮其他的波。
3. **N = 3的成長率理論上幾乎是0**（−6e−11）：
   - 量到+2.4e−8，差距在容許誤差內，但正負號不同。
   - 這麼小的數，正負號本來就量不出來，標準要求同號是我寫得不對。
   - 也因為這樣，「σ > 0的N」變成3～39，不是16～39。

除了這三種情況，N = 4～9、15～27、33～60都在容許誤差內。差距最大的是N = 26、27（約5e−5），N = 34以上大多在1e−9以下。

### M5a沒通過的原因

- 標準要求「完全均勻、不點的時候，t ≤ 600一直看起來均勻」，結果在t = 436.5就不均勻了。
- 診斷：浮點誤差（約10^−13）用成長最快的k=3的速度（σ = 0.077）長大，不是我寫標準時想的k=1（0.029），大約t = 330～440就會長到看得見。
- **600這個門檻，物理上就做不到。**是我寫標準時只看了k=1。
- 這不影響M5b：點一下的塞車在點之後89就出現，比浮點誤差長出來早很多。
- 但它影響第2頁的設計：讀者如果一直不點，車流大約t = 400之後會自己亂掉。

### M6沒通過的原因

- 跨越起點的檢查都通過了（0處不一致）。
- 但「追同一團塞車」失敗了，軌跡長度0。
- 診斷：t = 109.5時剛好有一台車的速度掉到0.1以下，下一個取樣點又回到0.100，於是軌跡馬上結束。
- 塞車在t = 120之後才穩定成形，到t = 220左右有5～6台車低於0.1。
- 標準把「開始追」定在第一次低於0.1，太早，量法是我設計錯的。

## 要使用者決定的事

M2、M5a、M6沒通過，都是我寫的標準或量法有問題，不是模型算錯。但照AGENTS第0節第5條，**標準要改要先問使用者**，所以停在這裡。

下面的修改建議都是**看過結果之後**才提的：

1. **M2的量法**：
   - k=1的波掉到10^−10以下就停止（比浮點誤差的底高兩個數量級）。
   - 其他任何一個波超過k=1的10%就停止。
   - 理論成長率的絕對值小於10^−8時，只比差距，不比正負號。
   - 「σ > 0的N剛好是16～39」這條不變。
2. **M5a**，兩個方向選一個：
   - (a) **建議**：讀者點之前，均勻車流直接用公式算位置（`x_n = n·b + V(b)·t`），不做數值積分，點下去那一刻才開始積分。這樣不點就永遠均勻，瀏覽器版也一樣。新的測試改成：點之前完全均勻；點之後的結果跟M5b一樣。
   - (b) 維持數值積分，把門檻改成t ≤ 300，讀者太久不點就自動重來。
3. **M6的追蹤**：
   - 改成至少3台車速度低於0.1時才開始追。
   - 連續5時間單位都找不到才算結束。
   - 其他條件不變。
4. **第三題**：
   - M9的結果算不算「明顯變差」？
   - 或者要不要把題目改成「平滑車開得比大家快還是慢比較好？」，因為「慢一點反而更平順」這個結果比較清楚。
   - 但任何新題目都要先寫標準再跑。
5. **R1的取捨**：R1效果最好，但平均車速掉了約21%。如果放進第8頁，要把「變平順但變慢」一起講。Stern的實驗C也有通過量小降，可以對照，但兩者條件不同。

修改後，只重跑沒通過的M2、M5a、M6，其他項目不重跑。
