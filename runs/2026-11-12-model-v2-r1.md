### M6v2：通過

- 跨越起點0處不一致。
- 從t = 212開始追到620，追了408時間單位。
- 波速c = −0.1505：0.5取樣和0.05取樣一樣，差0.00%。
- 車的平均速度是+0.9632。
- 車往前、塞車團往後，方向確認了。數值是無因次的，不換成km/h。

### M2v2：數值無法判定

- 新量法下，58個N裡**沒有任何一個跟理論不符**。第1次不符的N = 3、10～14、28～32都對上了，差距都在1.6e−5以下。
  - N = 10～14：k=1的波掉到1e−10就停。
  - N = 23～34：其他的波超過k=1的10%就停。
  - N = 3：只比差距。
- 但**N = 20、21的有效量測長度只有191、190**，不足標準要求的200，照規定標「數值無法判定」，M2v2整體不算通過。
  - 原因：這兩個車數成長最快（σ ≈ 0.030），k=1的波從1e−6長到1e−3只要約190時間單位，就碰到上限停止了。
  - 在這190時間單位裡，量到的σ跟理論差不到1e−8。但照標準，不能因此算通過。
- 資料足夠的56個N裡，σ_meas > 0的是16～19和22～39，就是16～39扣掉無法判定的20、21。程式輸出寫「不是剛好16～39」，原因就是這兩個N被排除了。

### M5a v2：第3項沒通過

| 小項 | 結果 |
|---|---|
| 1 點擊之前（解析解，t = 0～3000） | 通過：車速偏差0，車距最大偏差2.3e−13 |
| 2 切換的連續性 | 通過：位置、速度、時間差都是0 |
| 3 跟第1次M5b一致 | **沒通過**。點之後形成塞車的時間完全一樣（89.30），但被點那台的最低速度差1.1e−3（容許1e−6），t0 + 100的位置差7.8e−2（容許1e−6） |
| 4 很晚才點（t0 = 500） | 通過：點之後89.30形成塞車，跟t0 = 20時一樣 |

**第3項的原因**（診斷：`runs/logs/2026-11-12-model-v2-m5a3-diag.log`）：
- 差異不是切換時跳了一下，切換本身是連續的（第2項）。
- 差異來自**第1次M5b的煞車多算了一個子步**：
  - 第1次的做法從t = 0就數值積分。第399步的最後一個子步，時間是19.95 + 0.05，算出來是20.000000000000004，比20大一點點，所以煞車在那一個子步就生效了。
  - 新做法從點擊那一刻開始，時間從0算起，沒有這個問題。
  - 兩邊煞車生效的子步數是40對39，多的就是時間20.0那一個。
- 這一個子步造成的速度差約1e−3。在不穩定的條件下，100時間單位後放大成位置差約0.08。
- 換句話說，第1次M5b的煞車開始時間，被浮點捨入提早了一個子步。標準要求1e−6，在這種「煞車的開關卡在子步邊界上」的情況下達不到。

## 對其他項目的影響

- 核心求解器沒有改，所以第1次通過的M1、M3、M4、M5b、M5c、M7不用重跑。
- 但M5a v2-3發現，第1次M5b、M6、M7用的煞車，開始時間被浮點捨入提早了一個子步。它們的結論不受影響：
  - M5b：塞車形成的時間一樣（89.30）
  - M7：放大28倍、縮小到0.03倍的差距很大
  - M6：波速方向
- 但精確的數字，跟「從點擊那一刻開始積分」的做法有約1e−3的差距。

## 要使用者決定的事

**M5a v2-3**：
- (a) **建議**：把煞車的開始和結束，改成用步數判斷，不用浮點時間比大小。例如第400步到第409步煞車，同一步裡的4個子步一致處理。
  - 這是改核心求解器，照規定要重跑受影響的項目：M5b、M5c、M5d、M6、M7，以及M5a v2-3、M5a v2-4。
  - 好處是瀏覽器版對答案時，不會因為兩邊浮點捨入不同，而在煞車邊界上差一個子步。
- (b) 不改求解器，接受第3項沒通過，紀錄寫明原因。第2頁照新做法（點擊時才開始積分）製作。

**M2v2的N = 20、21**：
- (a) 照現在的結果，M2v2維持「數值無法判定」。第6頁的「16～39台」主張，在證據卡裡寫明：
  - 56個N的模擬跟理論相符
  - 20、21兩個N的模擬量測區間不足
- (b) 改初始擾動大小（例如1e−8），讓成長最快的N也有足夠的量測長度，再重跑M2。這是看過結果之後改標準，要照實記錄。
