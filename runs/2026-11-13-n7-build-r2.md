# 節點7：正式建置和測試（第2輪）

- **節點和輪次**：節點7第2輪。只修第1輪之後發現的一個問題，照graph.md「錯誤退回出問題的節點」，只改版面程式；網頁程式改了，所以節點7的測試全部重跑。
- **結果**：沙盒iframe的問題修好，新測試通過；其他測試重跑也通過。**效能測試第一次重跑沒通過**（Lighthouse 0.74），另外跑3次都通過，詳見下面。還沒有使用者驗收。

## 問題（使用者回報）

使用者在Claude的預覽面板打開`docs/index.html`，主控台出現：

> Uncaught SecurityError: Failed to execute 'pushState' on 'History' ... cannot be created in a document with origin 'https://www.claudeusercontent.com' and URL 'about:srcdoc'.

預覽面板用沙盒iframe（`about:srcdoc`、沒有同源）載入頁面。換頁時`history.pushState`被拒絕、丟出錯誤，換頁函式在切換頁面之前就中斷，**整份簡報停在第1頁**。第1輪的測試都用本機伺服器的正常網址開，沒有測到被嵌入的情況。

檢查同一個情況時另外找到兩個會壞的地方：
- 頁內連結（目錄、第10頁「答案在」）的`#p1`在`about:srcdoc`裡會被解讀成外層網頁的網址，點了會把iframe導走。
- Web Worker如果在沙盒裡載入失敗，原本只把Worker設成不用，已經送出去的計算永遠等不到回覆（第6頁會一直顯示「正在算」）。

## 修改

- `web/deck.js`（commit `e56dded`）：
  - 換頁時改網址的部分包在try裡；不能改網址就只換頁（返回鍵在這種環境沒有作用，正常網址不受影響）。
  - 頁內連結攔下來自己換頁，不交給瀏覽器。
  - Worker載入失敗時改在主執行緒算，已經送出去的計算重算一次。
- 新測試`tests/e2e_embedded.js`（commit `7ba2579`，正式執行前commit）：在`<iframe sandbox="allow-scripts" srcdoc>`裡跑三種情況：照原樣、Worker一建立就丟錯、Worker載入失敗。
- 重新建置`docs/index.html`（commit `7a5b3ca`）。

### 效能測試第1次沒通過

- 這次的修改只加了一個點擊事件和幾個try，不會讓載入多出1秒的阻塞。在跑正式測試之外，另外手動跑了3次Lighthouse也都是0.99、TBT 0～50 ms。
- 判斷是Lighthouse單次執行的波動，可能是測試機器那時候比較忙，但**原因沒查到**，不能確定。
- 標準沒改。第1次的紀錄保留，沒有用後面通過的結果蓋掉。
- 這代表現在「Lighthouse只跑一次」的標準本身不穩：同一份網頁可能這次過、下次不過。Lighthouse官方建議跑多次取中位數。要不要把標準改成「跑5次取中位數」，要使用者決定（改標準要先問）。
