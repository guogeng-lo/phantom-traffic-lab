# 節點7：Lighthouse標準修改（改成跑5次取中位數）

- **日期**：2026-11-13
- **授權**：使用者在節點7第3輪的授權裡同意（第4項）：「Lighthouse改成固定條件下跑5次取中位數。原本的分數、LCP、TBT、CLS門檻全部不變，修改標準先commit，再正式測試。保留5次完整結果，TBT超過1000ms的異常另外標記，不能直接忽略；若異常反覆出現，仍須調查。」
- **是不是看過結果才改的**：是。第2輪同一個版本（`docs/index.html` SHA-256 `952663b4…`），第1次是效能0.74、TBT 1,240 ms，沒通過（`runs/logs/2026-11-13-n7-r2-perf.log`）；後3次都是0.99、TBT 20／10／10 ms（`r2-perf-run2～4.log`）。第1次的原因沒有查到。第2輪的紀錄不改，那次照樣算沒通過。

## 改了什麼（`tests/perf_mobile.js`）

| | 修改前 | 修改後 |
|---|---|---|
| 次數 | 1次 | 連續5次，每次Lighthouse自己新開瀏覽器，條件一樣（手機、模擬慢速4G、CPU慢4倍、同一個網址`#p1`） |
| 跟門檻比的值 | 那1次的值 | 5次的中位數，每個指標分開取 |
| 門檻 | 效能≥0.9、LCP≤2.5 s、TBT≤200 ms、CLS≤0.1 | **不變** |
| 原始結果 | 印出1次 | 5次的分數、LCP、TBT、CLS、FCP全部印出來 |
| 異常 | 沒有 | 單次TBT超過1,000 ms，在那一行標「異常」。**異常2次以上算「反覆出現」，這一項沒通過**，要調查原因 |
| 跑不完 | 算沒通過 | 跑不完5次也算沒通過 |

「反覆出現」定成2次以上，是我依使用者的話訂的解讀。只出現1次時，中位數可以通過，但紀錄裡要寫出那一次、說明有沒有查到原因，不能略過。

動畫CPU、看不到時不算、DT=0.05這三項的標準都沒有改。
